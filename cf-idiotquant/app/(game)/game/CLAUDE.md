# `/game` — Rogue(1980) 클론

1980년 Rogue 를 웹으로 옮긴 것. 지하 26층의 **옌더의 증표**를 집어 1층으로 살아
돌아오면 이긴다. 죽으면 끝이다.

**발명한 것이 거의 없다** — 던전 생성·조명·전투·배고픔은 원작의 방식 그대로고, 새로
정한 것은 화면(DOM)과 손가락 조작뿐이다. 고치고 싶은 자리가 생기면 **원작이 왜 그렇게
했는지부터** 볼 것.

> **`NOTES.md` 가 이 문서의 전문이다.** 아래는 「무엇을 지켜야 하나」만 추린 것이고,
> 규칙 하나하나가 **어떤 사고를 치르고 생겼는지**는 그쪽에 있다. 아래 표의 「자세히」
> 칸에 적힌 제목으로 `NOTES.md` 를 찾으면 된다. **어떤 규칙을 지우거나 뒤집기 전에는
> 반드시 그쪽을 먼저 읽을 것** — 거의 다 한 번씩 실제로 깨져 본 자리다.

## 못 박은 규칙 넷

**새 규칙을 붙일 때 이 넷으로 판단한다.**

1. **화면은 규칙을 계산하지 않는다.** `perform(state, cmd)` 하나로만 판이 바뀐다.
   화면이 단추를 잠그는 것은 판단이 아니라 **값 읽기**이고(`onStairs`·`enchantTarget`),
   눌러도 엔진이 한 번 더 막는다 — **자물쇠는 둘이다.**
2. **한 값은 한 가지 일만 한다.** 걸음 = 배고픔. d20 = 명중. 갑옷+보호반지 =
   방어력(`heroArmor` 한 자리). **한 값을 두 곳에서 세지 않는다** — 갈리면 화면에 적힌
   값과 실제가 어느 날 달라진다. 새로 재고 싶은 것이 생기면 기존 값에 붙이지 말 것.
3. **아무 일도 안 일어난 행동은 턴을 안 쓴다.** 벽을 들이받으면 배가 안 고파진다 —
   `finishTurn(state, rng, acted)` 의 `acted` 가 그 자리다. 대상 없는 주문서도 같다.
4. **캔버스를 안 쓴다.** 던전은 `<pre>` 한 장이다. 단, **한 칸에 한 엘리먼트를 두지
   않는다** — 같은 색이 이어지는 구간을 한 덩어리로 묶는다(`MapView`).

## 캐릭터를 키우는 자리 — 강화

레벨업이 주는 것은 체력 +5와 네 레벨마다 숙련 +1뿐이다. **키우는 맛은 손에 쥔 것의
숫자가 낸다** — 리니지처럼 `+0 진은검`과 `+7 진은검`은 다른 물건이다.

레벨 특성(고를 것을 주는 것)도, 판을 넘는 메타 성장도 **안 한다.**
- 앞의 것은 원작 Rogue가 안 하는 것.
- 뒤의 것은 「죽으면 그것으로 끝」과 「도감이 죽어도 남는 유일한 것」을 깨뜨린다.
- 금화도 그대로 점수로만 둔다.

**강화를 캐릭터 성장의 자리로 삼은 까닭:**

1. **물건 사다리와 함께 간다** — 4층에서 주운 장검을 손질해 16층짜리를 앞서가게 할 수 있다.
   손잡이가 있어야 내려갈 이유가 산다.

2. **안전 구간이 있고, 종류마다 다르다** — 무기 `+6` · 갑옷 `+4`. 떨어지는 물건이 이미
   `+0~+3`이므로 안전 구간이 없으면 강화는 운 좋은 드랍과 같다. 갑옷이 두 칸 낮은 것은
   **한 칸의 무게가 다르기 때문**이다(갑옷 `+1`은 맞는 것 자체를 줄여 모든 싸움에 듣는다).

3. **실패하면 부서진다** — 수치가 내려가는 게 아니라 물건이 사라진다. 그것이 선택의
   값을 매긴다. 저주받은 물건도 강화할 수 있는데, 부서지면 저주에서 풀려난다(벗을 수
   없는 것을 떼는 유일한 길).

4. **상한이 `+9`다** — 상한이 없으면 운 좋은 초기 아이템이 25층짜리를 이겨서 내려갈
   이유가 사라진다.

5. **축복은 안전 구간 안에서만 다르다** — 한 번에 `1~3`칸을 올리되 천장에서 잘리고,
   그 위로는 일반과 똑같이 굴리고 똑같이 부서진다. 「안 부서지는 주문서」가 아니라
   **「안전 구간을 빨리 지나는 주문서」**다. 끝점(`+9`)은 안 움직인다.

6. **화면이 확률을 보여 준다** — 고르는 줄마다 `→ +7 (55%)`로 뜬다. 확률을 감추면 이건
   판단이 아니라 동전 던지기다. 내 물건의 값이므로 가릴 까닭이 없다(상대의 내역만
   도감이 잠근다).

자세한 논의는 [`NOTES.md`](NOTES.md#캐릭터를-키우는-자리는-강화다)를 참고.

## 고치기 전에 아는 것

어기면 **화면은 멀쩡하고 판도 돌아가는데 조용히 틀리는** 자리들. 왼쪽을 지키고,
건드려야 하면 오른쪽을 먼저 읽는다.

### 엔진

| 지킬 것 | 어기면 | 자세히 (`NOTES.md`) |
|---|---|---|
| 방어력을 뒤집는 자리는 `defenseOf` **하나** (`10 − 등급`, 0 이 바닥) | `+1` 갑옷이 숫자를 내려 나빠 보인다 | 「방어는 안쪽은 낮을수록」 |
| 여러 번 때리는 놈은 **대마다** 방어력을 깎는다 | 갑옷이 다중 공격에 듣는 점이 통째로 사라진다 | 「싸움은 대결 굴림과 깎는 갑옷」 |
| 특수 공격도 **대마다** 돈다 — 아쿠에이터는 `0d0` 이 둘이라 **한 턴에 갑옷 두 칸** | 「한 번 맞았는데 왜 두 칸이 녹나」가 판 어디에도 안 적힌다 | 「수법은 대마다 돈다」 |
| 그 수법은 **맞은 사람**에게 든다 (`special(state, m, hero, rng)`) | 협동에서 손님이 맞았는데 **방장의** 갑옷이 녹고 금화가 털린다 | 〃 |
| 도감의 `damage` 에서 `0d0` 을 **안 버린다** — 그게 곧 대의 수다 | 아쿠에이터가 「Dmg 없음」으로 떠서 대가 둘인 것이 안 보인다 | 〃 |
| 갑옷은 **수비 굴림에 안 붙는다** (붙는 것은 숙련뿐) | 판금 한 벌에 싸움이 끝난다 | 〃 |

| 강화 수치를 읽는 자리는 `enchantOf` **하나** | 무기/갑옷 갈래가 흩어져 한쪽만 고치면 조용히 어긋난다 | 「캐릭터를 키우는 자리는 강화」 |
| 놓는 자리는 `setEnchant` **하나** — 무기는 `plusHit`·`plusDam` **둘 다** | 「명중은 +3 인데 피해는 +5」 가 조용히 생긴다 (축복이 여러 칸을 한 번에 올리며 드러났다) | 〃 |

| 몬스터 띠(`depthRange`)도 `randomMonsterChar` 와 같은 식 | 〃 | 「도감은 판을 넘어 남는다」 |
| 놓을 자리는 `freeSpot` — **걸어 들어갈 수 있는 칸만** | 계단이 바위 속에 박혀 **내려갈 수 없는 층**이 난다 | 「안 잡히는 고장이 다섯」 |
| 총량은 층이 정하고(`floorQuota`) 자리는 **넓이 몫**으로 나눈다(`itemSpots`) | 3×3 벽장에 물건이 흔하고 넓은 홀이 텅 빈다 | 「놓을 자리는 방의 넓이를 태워」 |
| 이미 살던 층에 `populate` 를 **또 부르지 않는다** | 오르내릴 때마다 몬스터와 물건이 불어난다 | 「지나온 층은 떠난 그대로」 |
| 딛고 선 층은 `state.levels` 에 **안 둔다** | 같은 층이 두 벌이 되어 어느 날 한쪽만 바뀐다 | 〃 |
| 겉모습은 `newGame` 에서 **한 번만** 섞는다 | 층마다 물약 색이 달라져 알아낸 것이 소용없다 | 「겉모습은 판에 한 번만」 |
| 도망친 것(`hp = 0`)은 `killMonster` 를 안 지난다 | 안 잡은 님프·레프러콘이 도감에 오른다 | 「도감은 판을 넘어 남는다」 |
| 넘겨받은 도감·수법을 `{ ...x }` 로 **베낀다** | 부르는 쪽(화면)의 객체가 게임 안에서 몰래 바뀐다 | 〃 |

### 도감 — **열쇠가 둘이다**

능력치는 **잡아야** 열리고(`bestiary`), 수법은 **당해야** 열린다(`specials`). 한 칸에
담으면 님프를 잡아 본 사람과 털려 본 사람이 같은 도감을 보는데, 둘이 아는 것은 다르다.

- **잡기 전에는 한 조각도 안 준다.** `Sighting` 의 스탯 칸이 통째로 `undefined` 다.
- **상대의 보정·방어력은 아는 종에게만** 펼친다 — 표의 값이라 도감이 뒷문으로 뚫린다.
  모르는 종에게는 굴린 **눈**만 주고 공격력 줄은 통째로 접는다(두 숫자면 역산된다).
- **`damage` 의 `"0d0"` 과 `MonsterDef.special` 은 한 짝**이다. 한쪽만 있으면 영영 안
  열리는 칸이거나 당하고도 비는 칸이 된다. 지금은 여섯(`A`·`N`·`W`·`L`·`I`·`F`) 다 돈다.
- **묶는 수법은 이미 묶인 사람에게 안 걸린다.** 잠은 턴당 1씩만 풀리는데 상대는 매 턴
  때리므로, 더하거나 다시 채우면 **영영 못 움직인다**(얼음괴물에게 299턴을 쟀다).
- **도감을 펴는 데는 턴을 안 쓴다** — `survey()` 는 `perform` 을 안 지난다.

### 던전 모양

「방과 방이 이어진다」를 통과하면서도 **사람만 헤매는** 고장이 따로 있다.

- 복도의 꺾임은 두 방의 **바깥 사이**, 그것도 **양 끝을 뺀 안쪽**에서 고른다.
- 「없는 방」이 **잎이 되면 안 된다** — 만들 때부터 길을 하나 더 물린다(지우면 방이 사라져
  다듬기로는 못 고친다).
- `pruneDeadEnds` 는 **잎사귀만** 뗀다 — 이어진 것은 못 끊는다. 훑는 범위는 **지도 전체**
  (테두리 포함)이고, 면제하는 것은 **미로의 안쪽뿐**(`inMazeInterior`) — 미로 **벽**에
  부딪혀 끝난 바깥 복도는 고장이다.
- 다듬기는 **비밀문을 정한 뒤**에 돈다 — 비밀문에 닿은 끝은 지름길이지 고장이 아니다.
- **비밀문은 신장 트리 밖의 통로에만** 난다 — 방의 문 개수로 고르면 딴 방이 갇힌다.
- 순서가 정해져 있다: **잇기 → 미로 → 문 잇기**. 미로 칸은 홀수 자리에만 선다.
- 문턱에서는 `roomAround` 로 방을 찾는다(`roomAt` 은 안쪽에만 박혀 있다). **미로는 뺀다.**

### 저장 — 제일 비싸게 치른 자리

**값을 더하면 이미 저장된 판에는 그 칸이 없다.** 화면은 멀쩡히 뜨고 **한 걸음 걷는
순간** 터지며, 새로고침하면 같은 저장을 다시 읽어 또 터진다 — 그 사람에게 `/game` 은
**영영 안 열리는 주소**가 된다. 실제로 그랬다.

- **값을 더하면 `storage.normalize()` 와 `test/rogue-storage.test.ts` 를 같이 고칠 것.**
  한 곳에서만 채운다 — 코드 여기저기에 `?? []` 를 흩뿌리면 규칙이 두 벌이 된다.
- 그 테스트가 지키는 것은 **성질**이다: 칸을 아무거나 하나 빼도 결과는 `null`(새 판)
  이거나 **끝까지 굴러가는 판**이어야 한다. 「불러와지긴 하는데 걸으면 터진다」는 없다.
- **규칙만 고치면 이미 저장된 판은 안 낫는다.** 새로 생기는 길을 막았으면 되읽을 때도
  고쳐야 끝이다(`fixLetters`·`liftEnchants`·`fillAppearances`).
- **표에 물건을 더하면 옛 저장에는 그 겉모습이 없다.** 그 한 종만 이름 없는 「주문서」로
  떠서 **못 알아보기는커녕 그것만 알아보게 된다** — `fillAppearances` 가 **빠진 것만**
  메우고, 있는 이름은 안 건드리며, **시드에서 굴려** 열 때마다 달라지지 않게 한다.
- 지도는 `Uint8Array` 라 `JSON.stringify` 로 끝나지 않는다. 몬스터의 `def` 도 참조라
  글자만 적는다. 저장 판(`VERSION`)은 값이 늘 때마다 올리고, **앞으로 나올 판은 안 읽는다.**
- **판을 넘어 남는 것은 셋뿐**이다 — 도감·수법·지난 판. `newGame` 에 넘기는 자리가
  둘이라(첫 로드·`restart`) **한쪽만 고치면 새 판이 기록을 빈 칸으로 덮어쓴다.**

### 화면

- **색은 `app/global.css` 의 `--rg-*` 하나에만 있다.** 화면 파일에 `#rrggbb` 를 적지
  않는다 — 한때 140군데에 흩어져 밝은 테마를 붙일 자리가 아예 없었다.
  `-dim`(기억)은 **테마마다 흐려지는 방향이 반대**다.
- **명령 단추는 세 칸 격자**이고 `Rogue.tsx` 에서 **세 개씩 묶어** 적는다 — 개수가
  3의 배수가 아니면 마지막 줄만 이가 빠진다(`test/rogue-layout.test.ts` 가 센다).
  이름은 **360px 칸에 들어가는 길이**로.
- 새 단추를 세우기 전에 물을 것: **던전을 걷는 동안 누르는가.** 아니면 「⚙ 옵션」 안이다.
- **방향판만 꾹 누르면 연타된다**(400ms 뒤 120ms 간격). 명령 단추는 한 번이 한 번이어야
  한다 — 「내려간다」가 연타되면 세 층이 지나간다. 겨누는 중에는 끈다.
- **계산 줄은 엔진이 `DETAIL`(`"· "`)로 표시하고 화면이 읽는다.** 화면이 다시 판단하면
  그 규칙이 두 벌이 된다. 위 두 줄 띠는 굴림을 걸러 내되 **결과 숫자 하나는 남긴다.**
- 상태 줄의 명중·피해·방어력도 **엔진이 낸다**(`heroHitBonus`·`heroAttackText`·
  `heroDefense`). 화면이 따로 더하면 적힌 값과 굴리는 값이 갈린다.
- 판을 바깥 눌러 닫는 조건은 **둘 다** 필요하다 — 누르기 **시작한** 자리도 바탕이어야
  하고(끌다 뗀 것), 누르는 순간이 아니라 **뗄 때** 닫는다(아래 단추로 새어 든다).
- 기억된 지도에 **몬스터를 그리지 않는다.** 상태 줄은 **한 줄**로 묶는다(세로는 지도의 것).
- **계속 서 있는 알림은 모서리 한 칸만 쓴다.** 끊김 안내는 우상단 `h-7 w-7` 단추
  하나이고 **본문은 눌러야** 펼쳐진다(`test/rogue-layout.test.ts` 가 둘 다 센다).
  지도 한가운데 위에 띠로 두면 390px 에서 단추까지 접히며 **내가 선 자리와 앞의 몬스터를
  덮고**(재 보니 13285px²), 지도 밖 한 줄로 내리면 **지도가 그만큼 준다.** 끊긴 동안에도
  방장은 계속 논다 — 가리는 것은 **내가 보자고 누른 순간**뿐이어야 한다. 잠깐 떴다 지는
  것(층 돌발 이벤트 배너)은 예외다.

## 검증

```bash
npx tsc --noEmit                        # 에러 0
npm test                                # 150개
npm run build                           # /game · /game/imf
node --experimental-strip-types --import ./test/register.mjs scripts/measure-rogue.mjs 300
```

봇은 **도망도 쉼도 모르고 계단만 보고 내려간다** — 여기 나오는 층수는 사람이 닿을 수
있는 깊이의 **아래쪽 경계**다. 지금 값: 죽는 층 **중앙값 11**. 표를 고쳤으면 **고치기
전에 이 값을 먼저 찍어 두고** 견줄 것. 봇은 주문서를 안 읽으므로 **강화는 이 자에 안
잡힌다** — 따로 시뮬레이션한다.

이 저장소의 방식: **재현 → 한 자리에서 고치기 → 성질을 거는 테스트 → 그 고친 자리를
되돌려 테스트가 실제로 깨지는지 확인 → 브라우저(390px)에서 눈으로.** 마지막에
**잰 것과 짐작한 것을 갈라서** 보고한다.

`test()` 하나가 **주제별 묶음**을 담는다(`// ── 이름` 으로 갈린 블록 여럿). 새 규칙은
`test()` 를 새로 세우기보다 **가까운 묶음에 블록을 하나 더** 넣는다. 한 블록 안에서
앞이 깨지면 뒤가 안 도므로, 각 주장에 **왜 깨졌는지 알려 주는 메시지**를 단다.

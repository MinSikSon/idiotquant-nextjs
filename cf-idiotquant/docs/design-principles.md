# IdiotQuant 디자인 원칙

투자 후보를 찾고, 비교하고, 근거를 확인하는 데 드는 조작과 대기를 줄인다.

참고: [Superhuman: 제품으로서의 속도](https://blakecrosley.com/ko/guides/design/superhuman). 참고 글의 수치와 예시를 서비스에서 검증된 성능으로 간주하지 않는다.

## 1. 판단의 흐름을 이어준다

- 발굴 → 비교 → 분석을 핵심 흐름으로 삼는다. 화면마다 목적은 다르지만 검색·버튼·숫자 표기는 같은 규칙을 따른다.
- 페이지 왕복 시 사용자가 얻은 결과와 입력 조건을 유지한다. 초기화는 명시적 동작으로 제공한다.
- 현재 화면을 다시 선택했을 때 URL의 종목이나 조건을 지우지 않는다.

## 2. 조작에는 즉시 반응하고, 데이터 상태는 정확하게 보여준다

- 필터 선택과 화면 전환의 피드백을 서버 응답이나 장식용 애니메이션 뒤로 미루지 않는다.
- 재조회 시 기존 결과를 보존하는 경우 현재 갱신 중임을 구분한다. 다른 종목의 이전 값을 새 종목의 값처럼 표시하지 않는다.
- 관심 종목처럼 되돌릴 수 있는 조작에는 낙관적 갱신과 실패 복구를 검토한다. 재무 수치·계산 결과는 실제 응답에 근거한다.
- 체감 속도는 측정한다. 참고 글의 50ms를 실측 성능이나 외부 API 응답 보장으로 표시하지 않는다.

## 3. 사용하면서 배운다

- 빠른 이동에는 메뉴명뿐 아니라 할 수 있는 일을 표시한다. 발굴·비교·분석의 직접 이동 키도 함께 노출한다.
- 키보드와 마우스·터치를 모두 지원한다. 입력 중이거나 다른 대화상자를 조작할 때 이동 단축키가 끼어들지 않는다.
- 온보딩 개선 시 설명을 늘리기보다 실제 후보 한 개를 열고 비교·분석을 경험하게 한다.

## 4. 숫자와 근거에 시선을 모은다

- 본문은 중성 표면, 얇은 구분선, 일관된 텍스트 계층을 사용한다. 강조색은 선택·주요 행동·의미 있는 상태에 쓴다.
- 재무 기준일·수집일·출처는 의미를 구분한다. 미확인 값을 최신 또는 0으로 꾸미지 않는다.
- 수치에는 단위와 정렬을 맞추고, 필요한 순간에 설명을 제공한다.
- 홈의 3D는 서비스의 첫인상을 담당한다. 데이터 화면의 핵심 조작과 읽기를 방해하지 않도록 유지한다.

## 이번 적용 범위

- 기존 빠른 이동 메뉴에 업무 설명·검색 키워드·현재 화면 표시를 추가했다.
- Alt+1(발굴), Alt+2(비교), Alt+3(분석)를 제공한다. Mac에서는 Option 키로 안내한다.
- 검색 결과를 화살표로 선택할 때 선택 행을 스크롤 영역 안에 유지한다.
- 입력·한글 조합·다른 대화상자를 보호하고, 현재 경로를 선택하면 기존 URL과 결과를 유지한다.

결과 보존, 낙관적 갱신, 실습형 온보딩, 실제 성능 측정은 각 화면을 수정할 때 별도 검증할 원칙이다. 이번 변경에서 전체 화면의 완료를 의미하지 않는다.

## 반응 속도 점검 — 2026-10-17

- 분석 검색의 자동완성이 매 입력마다 종목 전체의 초성·한글 자모를 변환하고 있었다. 목록이 바뀔 때 검색 인덱스를 만들고 입력 시 재사용하도록 수정했다.
- 저장소의 실제 검색 목록 11,756개와 15개 검색어로 비교했다. Node 환경에서 예열 후 각 방식 375회 측정한 함수 실행 시간은 중앙값 0.99ms → 0.24ms, 95백분위 1.82ms → 0.34ms였다. 인덱스 최초 생성은 2.22ms였다. 검색어 및 목록에서 추출한 표본으로 기존 구현과 결과·순서를 대조했다.
- 이 수치는 로컬 함수 벤치마크이며 실제 브라우저 입력 반응 시간(INP), 렌더링, API 대기 시간을 포함하지 않는다. 작은 CPU 비용을 줄인 결과이므로 사이트 전체가 같은 비율로 빨라졌다는 의미는 아니다.
- 스크리너는 상세 필터가 닫혀 있으면 서랍에만 쓰는 누적 집계 10회와 단계별 집계 7회를 건너뛴다. 열 때는 최신 조건으로 계산하며 실제 필터 결과는 그대로 유지한다.
- Chrome DevTools MCP가 없어 브라우저 성능 수치는 측정하지 못했다. 추가 측정에서는 분석 최초 검색·발굴 필터 입력·비교 종목 추가를 구분하고, 입력부터 화면 갱신까지의 시간과 네트워크 대기를 따로 기록한다.
- 비교 일괄 가져오기는 현재 종목별 순차 요청을 사용한다. 외부 API 호출 한도를 확인한 뒤 제한적 병렬화의 효과와 오류율을 함께 측정할 후속 대상이다.

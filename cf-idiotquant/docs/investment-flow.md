# 매일 쓰는 투자 확인 흐름

기본 흐름은 **오늘의 관심종목 변화 → 필요한 종목 분석 → 확인 완료**다.
새 후보가 필요할 때 발굴을 열고, 후보가 여러 개일 때 비교한다.

- 주 메뉴는 오늘·발굴·더 보기. 분석·비교·기존 보조 도구는 더 보기에서도 접근한다.
- 로그인 홈은 계정의 관심종목 전체와 마지막 확인 이후 변화를 보여 준다. 비로그인 홈은 검색·발굴·저장 안내를 제공한다.
- 가격·PER·PBR·NCAV·전략 조건을 종목별 스캔 날짜로 비교한다. 가격 변화는 전일 대비 등락률이나 실시간 시세가 아니다.
- 조회·새로고침·분석 이동은 확인 기준을 바꾸지 않는다. ‘확인 완료’를 직접 눌러 저장한 값만 다음 비교 기준이 된다.
- 최초 사용은 명시적으로 기준을 설정한다. 기존 localStorage의 자동 저장본은 계정 기준으로 이전하지 않는다.
- 새 종목은 새로 추가됨으로 표시한다. 스캔 데이터가 없거나 기존 기준보다 과거라면 비교에서 제외하고 기존 기준을 유지한다.
- 저장 실패는 기존 변화와 기준을 유지한다. 버전 충돌은 최신 기준을 다시 읽고 사용자 확인 없이 저장을 재시도하지 않는다.
- 발굴의 전략·고급 필터·보기 설정·복사·공유는 접힌 보조 영역으로 제공한다. URL·저장 필터와 기존 결과 보기는 유지한다.
- 분석은 핵심 지표와 관심 저장을 먼저 보여주고 가치평가·기술적 지표·위험·재무·차트·공유를 펼쳐서 확인한다.
- 분석에서 출발한 발굴 목록의 조건·스크롤로 복귀하며, 홈에서 진입했다면 오늘로 돌아간다.
- 비회원의 관심 저장은 로그인 후 같은 종목으로 이어간다. 같은 탭의 30분 이내 요청만 처리하고 이미 저장한 종목은 해제하지 않는다.
- 비교는 종목부터 추가하면 오늘 이전의 최근 거래일 가격으로 시작한다. 기존 저장본은 복원하고 과거 날짜·수익률은 펼쳐서 확인한다. 선택 한도는 비회원 4종목·회원 20종목이다.

## API와 저장

기존 `/user/likes`의 저장·해제 계약은 유지한다.

- `GET /user/likes/review`: `{ success: true, data: { items, baseline: { revision, items, confirmedAt } } }`.
- `POST /user/likes/review`: `{ revision, items }`를 받아 저장된 baseline을 `data`로 반환한다. items는 사용자가 화면에서 본 스냅샷이다.
- 스냅샷은 market(KR/US)·ticker·name·scanDate(YYYYMMDD)·strategies·price·per·pbr·ncav로 구성한다. 숫자 결측값은 null이다.
- 인증된 계정의 관심종목만 저장할 수 있다. 클라이언트가 사용자 ID를 지정하지 않는다. 응답은 캐시하지 않는다.
- D1 `watchlist_reviews`는 사용자당 최신 확인본 한 행만 유지한다. revision의 조건부 쓰기로 동시 갱신을 검출하며 충돌은 409, 유효하지 않은 입력은 400이다.
- 삭제된 관심종목은 다음 확인 완료 시 기준에서 제외된다. 누락·과거 데이터와 결측 지표는 기존 기준을 지우지 않는다.

## 적용 순서와 검증

1. Worker의 `0047_watchlist_reviews.sql` 마이그레이션을 적용하고 API를 배포한다. 런타임 마이그레이션 목록에도 등록되어 있다.
2. API 인증·계정 분리·동시 갱신을 확인한 뒤 프론트를 배포한다. 기존 관심종목 API와 주소는 그대로 동작한다.
3. 휴대폰과 PC에서 같은 계정의 확인 상태가 이어지는지 확인하고, 1주일 동안 본인의 확인 시간을 살펴본다. 목표는 상세 영역을 펼치지 않아도 1분 안팎으로 변화 유무를 판단하고 완료하는 것이다.

프론트 `npm run check`, `npm run build`, Worker `npm test`, `wrangler deploy --dry-run`으로 검증한다.
`test/home-watchlist.test.ts`는 자동 확인 방지·중복 완료·저장 실패·버전 충돌·지연 조회를 실행 검증한다.
`test/worker-integration.test.ts`는 프록시 JWT와 실제 workerd·로컬 D1으로 새 API의 저장·재조회·계정 격리·동시 갱신을 검증한다. 실행 방법은 `service-improvements.md`를 참고한다.

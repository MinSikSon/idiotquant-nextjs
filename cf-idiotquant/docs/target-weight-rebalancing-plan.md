# 종목별 목표 비중 리밸런싱 구현 계획

검토일: 2026-11-05
상태: 설정·미리보기 및 수동 주문·일회/주간/월간 예약 실행 구현. 운영 반영 전 0042 마이그레이션 필요.

## 목적

사용자가 그룹 내 종목별 목표 비중을 지정하고 실제 보유 평가액을 기준으로
부족 종목을 매수하거나 초과 종목을 매도하여 목표에 접근한다.
적립금 배분 비율 변경만으로는 가격 변동에 따른 보유 비중을 교정할 수 없다.

## 현재 구조

- 프론트 `lib/features/capital/capitalSlice.tsx`: 그룹별 월 예산·방향·DCA 설정.
- Worker `src/trading/conditions.js`: 활성 종목에 적립 포인트 균등 배분.
- Worker `src/trading/kr.js`, `us.js`: 종목별 포인트와 매매 조건으로 주문.
- 기존 `portfolio_weight`는 미국의 매수금액 기준 종목당 상한 검사다.
  목표 평가액까지 매수·매도하는 기능이 아니며 DCA에서는 해당 조건을 우회한다.
- 기존 필드의 의미를 바꾸지 않고 별도 목표 비중 설정·계산기를 추가한다.

## 사용자 설정

그룹 운용 모드를 기존 퀀트 / 정액 적립 / 목표 비중으로 구분한다.

| 항목 | 예시 및 정책 |
| --- | --- |
| 종목별 목표 비중 | 40%, 35%, 20% |
| 목표 현금 비중 | 5% |
| 실행 방식 | 부족 종목 매수만 / 초과 종목 매도 포함 |
| 실행 조건 | 수동 / 주간·월간 / 비중 이탈 시 |
| 허용 오차 | 목표 대비 ±3%p 등, 예시는 권장 투자 수치가 아님 |
| 최소 주문금액 | 미달하면 다음 실행까지 보류 |

종목과 현금의 합계를 100%로 검증한다. 비중은 정수 단위(예: bp)로 저장한다.
매수만 모드는 신규 자금이 부족하면 목표에 도달하지 못할 수 있음을 표시한다.

## 자산 범위와 현금

초기 버전은 KR·US를 분리하고 그룹 등록 종목과 그룹 배정 현금만 대상으로 한다.
미국 그룹은 동일 통화로 평가하고 원화 예산을 환산하는 기준을 명시한다.

```text
그룹 운용자산 = 대상 종목 현재 평가액 합계 + 그룹 배정 현금
목표 평가액 = 그룹 운용자산 × 목표 비중
조정 필요액 = 목표 평가액 − 현재 평가액
```

예: 운용자산 1,000만 원, A 600만 원·B 300만 원·현금 100만 원,
목표 A 50%·B 40%·현금 10%라면 A 100만 원 매도, B 100만 원 매수가 계획이다.
실제 수량에는 1주 단위, 비용, 가격 변동과 주문가능금액을 적용한다.

- 적립 포인트는 실제 예수금이 아니므로 현금으로 합산하지 않는다.
- 여러 그룹이 계좌 현금을 중복 사용하지 않도록 배정·예약을 관리한다.
- 실제 주문은 증권사의 주문가능금액·매도가능수량으로 다시 제한한다.
- 수동 매수한 동일 종목도 초기에는 계좌 전체 보유수량에 포함한다고 안내한다.
  자동매매 물량만 분리하려면 별도 수량 장부가 필요하다.
- 대상 밖 보유 종목은 자동 매도하지 않는다.

## 실행 흐름

1. 잔고 전체(연속 조회 포함), 현재가, 주문가능금액, 미체결 주문을 조회한다.
2. 현재·목표 비중을 비교한다.
3. 허용 오차·최소 주문금액·정수 수량·비용 여유를 반영한 계획을 생성한다.
4. 매도 포함 모드에서는 초과 종목 매도를 먼저 진행한다.
5. 체결과 실제 주문가능금액을 확인한 뒤 부족 종목을 매수한다.
6. 실제 체결 결과로 비중을 재계산한다.

주문 접수를 체결이나 현금 확보로 간주하지 않는다.
주문번호와 접수·부분체결·체결·취소·확인 필요 상태를 영속 저장한다.
응답이 끊긴 주문은 조회로 확인하고 즉시 재전송하지 않는다.
수동·예약 실행이 겹치더라도 계좌 단위로 주문과 현금 사용을 직렬화한다.
미체결 주문은 예정 수량과 예약 현금에 반영해 중복 주문을 방지한다.

참고: [한국투자증권 주문·미체결·체결 설명](https://apiportal.koreainvestment.com/toolkit-strategy)

## 기존 전략과의 관계

- 목표 종목은 사용자가 고정한다. NCAV 순위나 active_count로 자동 제외하지 않는다.
- 주문 방향은 기존 그룹 side가 아니라 목표와 현재 비중의 차이로 결정한다.
- 동일 그룹의 포인트 기반 주문과 리밸런싱 주문을 동시에 실행하지 않는다.
- 거래정지·시세 오류 시 해당 금액을 현금으로 남기고 미실행 사유를 표시한다.
- 종목 삭제는 전량 매도로 해석하지 않는다. 청산은 명시적인 별도 동작으로 둔다.
- 실행 중 설정이 바뀌면 저장된 설정 버전을 확인하고 남은 계획을 중단·재계산한다.

## 구현 구조

- 그룹 설정에 목표 비중 정책, 종목별 비중과 목표 현금 비중을 추가한다.
- 순수 계산기는 국내·미국 공통으로 구현한다.
- 잔고·시세·통화·주문 처리는 시장별 어댑터로 분리한다.
- 설정·실행 계획·주문 상태를 분리 저장한다.
- 미리보기와 실제 실행은 같은 계산기를 사용한다.
- 화면에 현재 비중 / 목표 비중 / 차이(%p) / 예상 주문수량 / 미실행 사유를 표시한다.

## 단계별 구현과 검증

1. 설정 저장 + 주문 미리보기: 합계 검증, 현금·평가액 범위, 수량 계산 확인.
2. 수동 실행: 체결 추적, 현금 예약, 중복 실행 방지 검증.
3. 예약 실행: 주기·허용 오차 정책과 재실행 복구 검증.

필수 검증 사례: 부분체결, 미체결 재실행, 주문 응답 유실, 현금 부족,
고가 종목의 1주 미만 부족액, 연속 잔고 조회, 거래정지, 오래된 시세,
실행 중 설정 변경, 수동 실행과 스케줄 중복, 기존 전략과 현금 경합.

첫 구현 범위는 그룹별 목표·현금 비중, 매수만/매도 포함 선택,
주문 미리보기와 수동 리밸런싱으로 제안한다.
예약 실행은 체결 추적과 복구가 검증된 뒤 추가한다.

## 선행 작업

현재 자동매매 UI의 퀀트와 DCA 모드를 먼저 명확하게 구분한다.
이 UI 정리는 리밸런싱 기능 구현과 분리하여 진행한다.

### 선행 UI 구현 (2026-11-06)

`/balance` 국내·미국 그룹의 매매 설정에서 전략 화면 선택과 서버 적용을 분리했다.
퀀트·정액 적립 선택과 필드 편집은 로컬에서 처리하며, 적용 버튼에서만 기존 그룹
저장 API를 호출한다. 현재 적용된 전략과 미적용 편집 상태를 구분한다.
기본값 복원도 적용 전에는 서버에 반영하지 않는다.

저장 중 중복 적용을 차단하고 실패 시 편집값을 유지한다. 편집 도중 서버 설정이
변경되면 최신 설정을 다시 열도록 안내하여 오래된 값으로 덮어쓰는 것을 막는다.
이 선행 단계에서는 목표 비중을 준비 중 화면으로 제공하며 적용을 차단했다.
목표 비중 설정 저장·주문 미리보기는 아래 1단계에서 구현했고, 실제 주문은 아직 미구현이다.


### 1단계 구현 (2026-11-07)

국내·미국 그룹의 목표 비중 편집기에서 종목·현금 합계 100%를 검증하고,
기존 그룹 업데이트 API로 rebalancing 정책을 저장한다. 비중은 정수 bp,
금액은 국내 원·미국 센트로 저장한다. 종목 등록 순서로 매수 예산을 배분한다.
기본값은 현금 100%, 허용 오차 0%p, 최소 주문금액 0, 매수 전용이며 투자 권장값이 아니다.

미리보기 경로는 POST /kr/capital/groups/:id/rebalance-preview 및
POST /us/capital/groups/:id/rebalance-preview다. 관리자 권한으로 선택 계좌의
전체 잔고(연속 조회)와 등록 종목 시세를 조회하고, 미저장 편집값으로도 미리보기를 제공한다.
종목명과 코드가 같은 종목으로 해석되면 중복 평가를 막기 위해 전체 미리보기를 거부한다.
잔고 중간 오류·반복 커서·종목 코드 해석 실패·시세 오류 시 미리보기를 생성하지 않는다.
미국 모의투자는 기존 NASD 잔고 API가 다른 거래소를 포함하지 않아 미리보기를 차단한다.

미리보기는 현재/목표 평가액·비중·차이·예상 수량·미실행 사유를 표시한다.
정수 수량·허용 오차·최소 금액·매도가능수량과 매수 비용 여유 0.3%를 반영한다.
매도대금은 미리 매수에 합산하지 않으며, 매도 체결 후 재조회가 필요하다.
조회는 주문이나 자본 상태 저장을 호출하지 않으며 응답은 no-store다.

현재 배정 현금은 사용자가 입력한 계산값이다. 실제 계좌 예수금·주문가능금액,
미체결 주문·시세 지연·거래정지 여부와 그룹 간 현금 예약은 아직 검증하지 않는다.
따라서 이 단계의 수량은 실제 주문 가능한 수량을 보장하지 않는다.
실제 주문·예약 실행 버튼은 제공하지 않는다.

목표 비중 그룹은 기존 NCAV 선정·포인트 주문·자동 리필에서 제외하지만 등록 종목과
기존 포인트는 보존한다. 기존 퀀트·정액 적립으로 적용하면 정책을 명시적으로 해제한다.
편집 중 서버 설정이나 소속 종목이 변경되면 적용을 차단하며, 설정 변경 뒤 이전
미리보기를 숨긴다. 저장·조회 중 중복 요청을 막고 실패 시 입력값을 유지한다.
종목 이동·삭제는 청산이 아니며 다음 설정·미리보기 시 종목 구성이 맞는지 재검증한다.

별도 D1 마이그레이션은 필요하지 않다. Worker를 먼저 배포한 뒤 프론트를 배포해야 한다.
이 작업에서는 배포·운영 데이터 변경·실계좌 주문을 실행하지 않았다.

다음 단계는 계좌 단위 직렬화와 설정 버전 관리, 실제 주문가능금액·미체결 조회,
현금 예약, 주문 영속 기록·체결 추적·응답 유실 복구를 갖춘 수동 실행이다.
기존 자본 JSON 전체 저장과 스케줄 실행 사이의 동시 변경 처리도 함께 보완해야 한다.


### 2·3단계 구현 (2026-11-07)

수동 실행과 일회·주간·월간 예약을 같은 실행기로 연결했다. 예약 일시는 한국 시간으로
입력하고 UTC로 저장한다. 주간은 7일 간격, 월간은 한국 시간 같은 날짜·시각(1~28일)이다.
예약 시각 이후 시장별 정규장 실행 구간(KR 09:05~15:15, US 뉴욕 시간 09:35~15:45)에
진행한다. 미국 서머타임을 반영하며, 휴장·거래정지는 증권사 응답에 따라 대기·거절 처리한다.
누락된 과거 주기를 한꺼번에 실행하지 않고 가장 최근 회차만 처리한다.

실제 주문은 조회한 가격을 지정가로 사용한다. 매도 단계가 끝나기 전에는 매수를 보내지
않으며, 매도 체결 금액과 새 잔고로 매수 계획을 계산한다. 1회 호출에서 신규 주문은 최대
한 건이다. 접수·부분체결은 다음 분 스케줄 또는 화면의 이어가기에서 다시 조회한다.
조회만 하는 5초 화면 폴링은 주문을 전송하지 않는다.

D1의 rebalancing_runs에 정책·실행 요청 키·진행 단계·주문 전송 의도·주문번호·체결 누계와
현금 반영 누계를 저장한다. 전송 의도를 저장하지 못하면 주문을 보내지 않는다.
처리 lease는 2분이며, lease를 잃은 호출은 상태를 저장하거나 다음 주문을 시작할 수 없다.
부분체결의 금액 차이만 현금 장부에 한 번 반영하며, 실제 비용 대신 매수 +0.3%·매도 -0.3%의
보수적인 비용 여유를 장부에 적용한다. 실제 계좌 수수료·세금과 동일하다는 뜻이 아니다.

rebalancing_cash는 그룹별 실제 실행 장부다. 최초 실행 시 배정 현금으로 시작하며, 같은
배정값을 유지하면 다음 실행에도 체결 후 잔액을 사용한다. 배정 현금을 다른 값으로
저장하면 다음 실행 준비 시 새 값으로 재배정한다. 다른 그룹의 장부 현금은 매수에 사용할 수
없으며, 기존 퀀트·정액 적립·화면 수동 주문도 공통 주문 경로에서 이 예약 현금을 제외한다.
미국은 환전 후 가능액을 사용하지 않는다. 실제 주문가능금액·가능수량으로 매번 다시 제한한다.

계좌 API 주소·계좌번호·상품코드를 해시한 trading_account_guards로 실제 계좌 전체를 잠근다.
리밸런싱 중 기존 주문·다른 그룹 실행·그룹 설정 및 종목 이동/삭제를 차단한다. 설정을
변경하려면 남은 주문을 중단하고 접수 주문의 체결·취소 정산을 마쳐야 한다.
동일 시장의 같은 실계좌를 여러 자동매매 계정으로 중복 등록한 경우 실제 실행을 거부한다.
오래된 배치의 자본 저장은 최신 그룹 정책과 종목 이동·삭제를 보존하며 CAS로 저장한다.
이전 전략에서 이미 판단 중이던 주문도 증권사 전송 직전에 최신 그룹 구성을 다시 확인한다.

응답 유실·저장 결과 불명·조회 오류는 계좌 잠금을 유지하고 확인 필요로 남긴다.
주문번호가 없는 주문은 자동 재전송하지 않는다. 증권사에서 확인한 주문번호와 주문일자를
연결하면 종목·매매 방향·수량·지정가·주문 시각(전송 의도 시각과 5분 이내)을 확인한 뒤
체결 조회를 재개한다. 조회에서 주문을 찾지 못했다는 사실만으로 미접수로 간주하지 않는다.

남은 주문 중단은 이미 접수된 주문의 취소가 아니다. 접수 주문을 계속 조회·정산한 뒤
남은 계획을 멈춘다. 증권사에서 수동 취소한 결과도 체결 조회로 반영한다. 거절·최소 수량·
주문가능금액 부족을 같은 실행에서 반복 재주문하지 않으며, 처리 완료가 목표 비중에
도달했다는 보장은 아니다. 실행 기록과 마지막 조회 비중을 함께 확인한다.

API(국내 /kr, 미국 /us 동일):
- GET /kr/capital/groups/:id/rebalance-runs: 최근 10개 실행.
- POST .../rebalance-execute: request_key와 expected_policy로 중복 방지 및 최신 설정 확인.
- POST .../rebalance-resume: run_id의 체결 조회·최대 한 단계 진행.
- POST .../rebalance-stop: run_id의 남은 주문 중단 요청.
- POST .../rebalance-attach: run_id·broker_id·broker_date로 응답 유실 주문 연결.

모든 API는 기존 관리자 신원 확인 뒤 선택 계좌·그룹 소유 범위를 검사하고 no-store로 응답한다.
UI는 저장된 설정과 일치하는 미리보기가 있을 때 실제 실행 버튼을 제공한다. 예약 저장은
실제 자동 주문 예약이며, 계좌 ON·그룹 ON과 SCHEDULED_ON이 필요하다.

운영 반영 순서:
1. 신규 주문을 잠시 멈춘 상태에서 기존 Worker의 실행이 끝났는지 확인한다.
2. Worker migrations/0042_rebalancing_execution.sql을 D1에 적용한다.
3. 새 Worker를 먼저 배포하고, 그 다음 프론트를 배포한다.
4. 자동 주문에 사용할 계좌·그룹·배정 현금·예약 시각을 확인하고 ON으로 전환한다.

0042는 공통 주문 경로에서도 필요하다. 이전 버전 Worker가 동시에 주문을 보내는 롤링
기간에는 새 잠금을 알지 못하므로 주문을 활성화하지 않는다. 다운그레이드도 실행·미체결
정산과 잠금 해제를 확인한 뒤 진행한다.

계좌 잠금은 시간만으로 해제하지 않는다. 기존 주문이나 설정 저장 요청이 비정상 종료되어
legacy:/config: 잠금이 남은 경우, 또는 응답 유실 주문이 끝내 확인되지 않는 경우에는 자동
진행을 중단한다. 운영자는 해당 계좌의 스케줄과 사용자 주문 경로를 중지하고 진행 중인
호출이 종료되었으며 증권사 주문·체결·미체결이 모두 확인된 뒤 D1 잠금/실행 기록을 조사해야
한다. 화면에서 임의로 미접수 확정·잠금 강제 해제 기능은 제공하지 않는다.

증권사 API 규격은 한국투자증권 공식 open-trading-api의 주문·주문가능금액·체결·미체결
샘플을 확인했다: https://github.com/koreainvestment/open-trading-api/tree/main/examples_llm
미국 모의계좌는 전체 거래소 잔고 제한으로 계속 차단하며, 1달러 미만 종목은 소수 가격 단위
문제로 실제 주문을 차단한다. 배포·운영 D1 변경·실계좌 주문은 이 구현 작업에서 수행하지 않았다.

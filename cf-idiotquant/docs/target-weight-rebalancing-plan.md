# 종목별 목표 비중 리밸런싱 구현 계획

검토일: 2026-11-05
상태: 설계 제안. 미구현이며 설정값·기본 정책은 구현 전 확정한다.

## 목적

사용자가 그룹 내 종목별 목표 비중을 지정하고 실제 보유 평가액을 기준으로
부족 종목을 매수하거나 초과 종목을 매도하여 목표에 접근한다.
적립금 배분 비율 변경만으로는 가격 변동에 따른 보유 비중을 교정할 수 없다.

## 현재 구조

- 프론트 `lib/features/capital/capitalSlice.tsx`: 그룹별 월 예산·방향·DCA 설정.
- Worker `src/trading/conditions.js`: 활성 종목에 적립 포인트 균등 배분.
- Worker `src/trading/kr.js`, `us.js`: 종목별 포인트와 매매 조건으로 주문.
- 기존 `portfolio_weight`는 미국의 매수금액 기준 종목당 상한 검사다.
  목표 평가액까지 매수·매도하는 기능이 아니며 DCA에서는 해당 조건을 우회한다.
- 기존 필드의 의미를 바꾸지 않고 별도 목표 비중 설정·계산기를 추가한다.

## 사용자 설정

그룹 운용 모드를 기존 퀀트 / 정액 적립 / 목표 비중으로 구분한다.

| 항목 | 예시 및 정책 |
| --- | --- |
| 종목별 목표 비중 | 40%, 35%, 20% |
| 목표 현금 비중 | 5% |
| 실행 방식 | 부족 종목 매수만 / 초과 종목 매도 포함 |
| 실행 조건 | 수동 / 주간·월간 / 비중 이탈 시 |
| 허용 오차 | 목표 대비 ±3%p 등, 예시는 권장 투자 수치가 아님 |
| 최소 주문금액 | 미달하면 다음 실행까지 보류 |

종목과 현금의 합계를 100%로 검증한다. 비중은 정수 단위(예: bp)로 저장한다.
매수만 모드는 신규 자금이 부족하면 목표에 도달하지 못할 수 있음을 표시한다.

## 자산 범위와 현금

초기 버전은 KR·US를 분리하고 그룹 등록 종목과 그룹 배정 현금만 대상으로 한다.
미국 그룹은 동일 통화로 평가하고 원화 예산을 환산하는 기준을 명시한다.

```text
그룹 운용자산 = 대상 종목 현재 평가액 합계 + 그룹 배정 현금
목표 평가액 = 그룹 운용자산 × 목표 비중
조정 필요액 = 목표 평가액 − 현재 평가액
```

예: 운용자산 1,000만 원, A 600만 원·B 300만 원·현금 100만 원,
목표 A 50%·B 40%·현금 10%라면 A 100만 원 매도, B 100만 원 매수가 계획이다.
실제 수량에는 1주 단위, 비용, 가격 변동과 주문가능금액을 적용한다.

- 적립 포인트는 실제 예수금이 아니므로 현금으로 합산하지 않는다.
- 여러 그룹이 계좌 현금을 중복 사용하지 않도록 배정·예약을 관리한다.
- 실제 주문은 증권사의 주문가능금액·매도가능수량으로 다시 제한한다.
- 수동 매수한 동일 종목도 초기에는 계좌 전체 보유수량에 포함한다고 안내한다.
  자동매매 물량만 분리하려면 별도 수량 장부가 필요하다.
- 대상 밖 보유 종목은 자동 매도하지 않는다.

## 실행 흐름

1. 잔고 전체(연속 조회 포함), 현재가, 주문가능금액, 미체결 주문을 조회한다.
2. 현재·목표 비중을 비교한다.
3. 허용 오차·최소 주문금액·정수 수량·비용 여유를 반영한 계획을 생성한다.
4. 매도 포함 모드에서는 초과 종목 매도를 먼저 진행한다.
5. 체결과 실제 주문가능금액을 확인한 뒤 부족 종목을 매수한다.
6. 실제 체결 결과로 비중을 재계산한다.

주문 접수를 체결이나 현금 확보로 간주하지 않는다.
주문번호와 접수·부분체결·체결·취소·확인 필요 상태를 영속 저장한다.
응답이 끊긴 주문은 조회로 확인하고 즉시 재전송하지 않는다.
수동·예약 실행이 겹치더라도 계좌 단위로 주문과 현금 사용을 직렬화한다.
미체결 주문은 예정 수량과 예약 현금에 반영해 중복 주문을 방지한다.

참고: [한국투자증권 주문·미체결·체결 설명](https://apiportal.koreainvestment.com/toolkit-strategy)

## 기존 전략과의 관계

- 목표 종목은 사용자가 고정한다. NCAV 순위나 active_count로 자동 제외하지 않는다.
- 주문 방향은 기존 그룹 side가 아니라 목표와 현재 비중의 차이로 결정한다.
- 동일 그룹의 포인트 기반 주문과 리밸런싱 주문을 동시에 실행하지 않는다.
- 거래정지·시세 오류 시 해당 금액을 현금으로 남기고 미실행 사유를 표시한다.
- 종목 삭제는 전량 매도로 해석하지 않는다. 청산은 명시적인 별도 동작으로 둔다.
- 실행 중 설정이 바뀌면 저장된 설정 버전을 확인하고 남은 계획을 중단·재계산한다.

## 구현 구조

- 그룹 설정에 목표 비중 정책, 종목별 비중과 목표 현금 비중을 추가한다.
- 순수 계산기는 국내·미국 공통으로 구현한다.
- 잔고·시세·통화·주문 처리는 시장별 어댑터로 분리한다.
- 설정·실행 계획·주문 상태를 분리 저장한다.
- 미리보기와 실제 실행은 같은 계산기를 사용한다.
- 화면에 현재 비중 / 목표 비중 / 차이(%p) / 예상 주문수량 / 미실행 사유를 표시한다.

## 단계별 구현과 검증

1. 설정 저장 + 주문 미리보기: 합계 검증, 현금·평가액 범위, 수량 계산 확인.
2. 수동 실행: 체결 추적, 현금 예약, 중복 실행 방지 검증.
3. 예약 실행: 주기·허용 오차 정책과 재실행 복구 검증.

필수 검증 사례: 부분체결, 미체결 재실행, 주문 응답 유실, 현금 부족,
고가 종목의 1주 미만 부족액, 연속 잔고 조회, 거래정지, 오래된 시세,
실행 중 설정 변경, 수동 실행과 스케줄 중복, 기존 전략과 현금 경합.

첫 구현 범위는 그룹별 목표·현금 비중, 매수만/매도 포함 선택,
주문 미리보기와 수동 리밸런싱으로 제안한다.
예약 실행은 체결 추적과 복구가 검증된 뒤 추가한다.

## 선행 작업

이 UI 정리는 리밸런싱 기능 구현과 분리하여 진행한다.

### 선행 UI 구현 (2026-11-06)

`/balance` 국내·미국 그룹의 매매 설정에서 전략 화면 선택과 서버 적용을 분리했다.
퀀트·정액 적립 선택과 필드 편집은 로컬에서 처리하며, 적용 버튼에서만 기존 그룹
저장 API를 호출한다. 현재 적용된 전략과 미적용 편집 상태를 구분한다.
기본값 복원도 적용 전에는 서버에 반영하지 않는다.

저장 중 중복 적용을 차단하고 실패 시 편집값을 유지한다. 편집 도중 서버 설정이
변경되면 최신 설정을 다시 열도록 안내하여 오래된 값으로 덮어쓰는 것을 막는다.
목표 비중은 준비 중 화면으로 제공하며 적용은 차단한다.
목표 비중 설정 저장·잔고 기반 주문 미리보기·실제 리밸런싱 주문은 아직 미구현이다.

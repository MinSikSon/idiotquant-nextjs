한 서체, 두 굵기로 읽는 금융 화면

홈·공통·금융 화면의 타이포그래피를 Pretendard와 일반 400·강조 600으로 통일했다. 작은 설명문의 줄 높이는 최소 1.5로 맞추고, 계산기의 별도 고정폭 서체를 공통 산세리프로 바꿨다.

근거: 큰 효과를 만드는 작은 UI 디자인 팁들의 산세리프 단일화·두 굵기·문장형 대소문자·본문 줄 높이 원칙. 원문이 허용한 semi-bold 대안을 서비스 강조 굵기 600으로 채택했다.

이전

400 · 460 · 500 · 540
550 · 600 · 650 · 700 · 900

화면별 굵기가 달랐고, 계산기 숫자는 JetBrains Mono를 직접 지정했다. 12px 기본 본문 줄 높이는 16px, 14px은 20px이었다.

적용

일반 설명 400
제목·강조 600

숫자도 Pretendard로 읽되 tabular-nums와 우측 정렬을 유지한다. 12px은 18px, 14px은 21px 줄 높이를 사용한다.

범위와 예외

게임의 픽셀·고정폭 서체와 기존 굵기는 그대로 둔다. 관리자는 레이아웃 표식을 통해 새 굵기·줄 높이 토큰에서 제외한다. 모바일 상단바와 포털도 같은 금융 토큰을 상속한다. 큰 제목, 한 줄 종목명, 요약 수치, 조밀한 차트 축은 본문과 다른 줄 높이를 허용한다. 모든 작은 보조 레이블을 일괄 확대하지는 않았다.

브라우저에서 확인한 결과

  • 홈·분석 안내·발굴 결과·계산기·비교 화면의 표시 텍스트 굵기는 400·600으로 확인했다.
  • 모바일 390px 계산기·홈·분석·발굴과 데스크톱 1440px 비교 화면에서 문서 가로 넘침이 없었다. 계산기 숫자는 Pretendard와 tabular-nums를 사용한다.
  • 홈 설명 1.6–1.85, 분석 설명 1.6–2, 비교 설명 1.5–2의 줄 높이를 확인했다. 더 넓은 기존 줄 간격을 덮어쓰지 않는다.
  • 라이트·다크 테마에서 대표 화면을 확인했다. 임시 표본 화면에서 잔고 제목 600, 분석 제목 600, 지표 설명 400을 확인했다.
  • 임시 표본 화면에서 게임·관리자 표식이 있으면 기존 300·500·700·900 굵기가 유지되고, 금융 화면으로 이동하면 400·600으로 전환되는 것을 확인했다. 게임 고정폭 서체와 관리자 기존 산세리프 표시도 확인했다.

인증이 필요한 잔고·관리자 전체 흐름이나 실제 주문·가계부 저장은 실행하지 않았다. 해당 화면은 공통 CSS 표본과 소스 검토로 확인했다. 임시 검증 경로는 최종 소스에서 제거했다.

자동 검증

최종 소스의 npm run check에서 타입 검사와 테스트 586개가 통과했고, lint 오류는 0개였다(기존 경고 129개). npm run build도 통과했다. 임시 경로 제거 후 생성 캐시를 정리했고, 외부 Google Fonts 처리 오류는 소스 변경 없이 빌드를 재실행해 해소됐다. CI 상태는 PR에서 확인할 수 있다. 이 보고서는 UI 타이포그래피 적용 기록이며 전체 서비스의 접근성 인증을 의미하지 않는다.
